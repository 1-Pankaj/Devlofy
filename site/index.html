README.md

Why Devlofy exists

Most software asks you to sign in, sync up, and hand over your life. Devlofy was built on the opposite idea — the best tool is the one that simply stays with you. It opens in a blink, works on a plane, in a basement, on a train, and it remembers everything even when the internet doesn’t.

Your work deserves a home that doesn’t watch it.

  • Plan days in plain words — !3, 45m, tomorrow, #project are understood
  • A focus timer with streaks, feeding a private 3D garden
  • Client work, billable hours and invoices in one place
  • Cross-app search and a local engine that suggests next steps
  • JSON export, any time — leaving is allowed, so staying is a choice

Run it from source

No installer ceremony, no account, no email. Clone it and go:

$ clone the repo — or grab a build from Releases
git clone https://github.com/1-Pankaj/Devlofy.git
cd Devlofy
npm install
npx expo start   # then press a (Android) or w (web) — iOS is planned
Is Devlofy really free?

Yes — MIT licensed, fully open source. Use it, read it, change it, ship your own version. If it earns its place, a star helps more than you’d think.

Where exactly is my data?

In a local SQLite database on your device — on web, in your browser’s own storage. One tap exports everything to JSON whenever you want a copy.

Does it work without internet?

Almost everything does — that’s the point. Tasks, focus, the garden, notes, invoices and all eleven bench tools run fully offline. The GitHub and Sentinel panels simply wait politely for a connection.

How is this different from Notion or Trello?

Those tools live in someone else’s cloud and want an account before they show you anything. Devlofy lives where you live — your device — and never asks who you are. It’s not a workspace rental; it’s a workshop you own.

Security & privacy

Private isn’t a feature. It’s the floor.

Plenty of tools promise privacy in a settings page. Devlofy starts there — the privacy is in the architecture itself. There is no server to trust, because there is no server. Nothing to breach, nothing to sell, nothing to subpoena.

Important — what we collect

Nothing. No analytics, no telemetry, no crash reporting service, no accounts. The absence of a backend is the guarantee — there is no server to trust, breach, or subpoena.

Note — where your data lives

In a local SQLite database on your device. On web, SQLite runs as WebAssembly in your browser’s own storage. One tap in More dumps all of it to JSON, whenever you like.

Tip — the only two things that touch the network

GitHub (only when you connect an account) and Sentinel (only when you open the board or press check). A GitHub token is verified before it is saved, and kept out of the export file.

Verification

Don’t trust this page. Run the checks.

The repo ships its own proof. Every claim above is one clone away from being true in your terminal — no progress bars, no promises, just commands and their results.

npm run check

Typecheck, lint, and 482 known-answer checks in one command — 190 for the notes block model, 122 for the Engine, 90 for Sentinel, 80 for the Bench.

npx expo export --platform web

The full web build, which validates the WebAssembly SQLite and the 3D renderer — the two parts most likely to silently break.

MIT, with a NOTICE file

Every dependency’s license is auditable — npm ls --all gives the authoritative list per package. Read it, then decide.

482 checks, zero mock data

The suites are known-answer checks — fixed inputs, expected outputs — and tools/checks/self-check.sh runs every one of them with a single command.
